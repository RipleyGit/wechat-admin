# 模板消息推送接口对接文档

面向**外部业务系统**的接口对接说明。接入方通过一个 HTTP 接口，向指定公众号的粉丝发送微信模板消息。

本文只讲**怎么调、传什么、返回什么、错了怎么办**。

---

## 一、能力边界

先确认这些限制是否影响你的场景，再往下读：

| 项目 | 说明 |
| --- | --- |
| 发送对象 | 只能是**已关注该公众号**的粉丝。已取关用户无法接收，且会导致整批失败 |
| openid | 是**公众号 openid**，不是小程序 openid，两者不通用 |
| 收件人上限 | 单次请求最多 100 人（数组元素总数与解析去重后的人数都不能超） |
| 模板 | 必须是该公众号后台**已经添加过**的模板，不能凭空创建 |
| 发送方式 | 同步返回结果；不提供异步批次、不提供定时发送 |
| 客服消息 | 暂未开放，本版本只支持模板消息 |

接口是**机器对机器**调用，没有前端页面，也不走登录态。

---

## 二、接入准备

### 2.1 拿到推送密钥

一个密钥对应**一个公众号**。不同公众号用不同密钥，不能混用。

获取方式：登录运营台 `https://wechat.bleem.site` →「公众号管理」→ 编辑目标公众号 →「推送密钥」→ 生成 / 复制。

也可以在同一个位置扫「扫码获取接入信息」的二维码，手机上直接显示**公众号名称、类型、AppID、推送地址和密钥**，不用手工抄。二维码里的 token 10 分钟内有效，过期在后台点「刷新」重新生成。

密钥是 48 位十六进制字符串，等价于该公众号的消息发送权限：

- 只放在服务端，**不要**下发到小程序、H5、App 或任何客户端
- 不要提交到代码仓库，用环境变量或配置中心管理
- 泄露后立即在运营台重新生成，旧密钥即刻失效

### 2.2 确认模板

模板必须已在公众号后台（微信公众平台 → 模板消息 → 模板库）添加。把模板 ID 和模板内容一起交给接入方，例如：

```text
模板 ID：9bRzXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX
模板内容：
  您有一条新工单
  工单编号：{{keyword1.DATA}}
  提交时间：{{keyword2.DATA}}
  备注：{{remark.DATA}}
```

`{{keyword1.DATA}}` 里的 `keyword1` 就是请求 `data` 里要传的 `name`。

### 2.3 扫码获取接入信息（运营人员使用）

运营台「编辑公众号 → 推送密钥」下方有一个二维码，运营人员用手机扫码即可看到该公众号的接入信息，不必手工抄写。这条链路涉及两个接口，**接入方通常不需要直接调用**，了解即可。

**第一步：后台生成二维码 token**（需要登录运营台，且拥有该公众号的配置权限）

```http
GET /manage/console/account-config/{appid}/push-qrcode
```

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "token": "b3f1c2a4d5e6478a9b0c1d2e3f4a5b6c",
    "expiresIn": 600
  }
}
```

- `token`：32 位十六进制随机串，10 分钟过期
- `expiresIn`：有效期，单位秒
- 该公众号还没生成推送密钥时返回 `code=400`（`请先生成推送密钥`）

二维码内容是 `{运营台地址}/push-info/{token}`。

**第二步：手机扫码读取信息**（匿名，靠 token 鉴权）

```http
GET /wx/push-info/{token}
```

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "name": "美利善服务号",
    "type": 1,
    "appid": "wx62c3973df7065a2b",
    "notifySecret": "0123456789abcdef0123456789abcdef0123456789abcdef"
  }
}
```

| 字段 | 说明 |
| --- | --- |
| `name` | 公众号名称 |
| `type` | `1` 服务号，`2` 订阅号 |
| `appid` | 公众号 AppID |
| `notifySecret` | 推送密钥，48 位十六进制 |

返回头带 `Cache-Control: no-store`。token 失效返回 `code=400`，公众号已删除返回 `code=404`。

## 三、接口定义

### 3.1 基本信息

| 项目 | 值 |
| --- | --- |
| 地址 | `https://wechat.bleem.site/wx/push/template` |
| 方法 | `POST` |
| Content-Type | `application/json; charset=utf-8` |
| 鉴权头 | `X-Notify-Secret: <推送密钥>` |
| 公众号标识 | **不传**。服务端按密钥反查是哪个公众号，所以不同公众号必须用各自的密钥 |

> ⚠️ 路径里的 `/wx` 不能省，少了会 404。

### 3.2 请求体

```json
{
  "templateId": "9bRzXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX",
  "data": [
    { "name": "keyword1", "value": "A-20261113-001" },
    { "name": "keyword2", "value": "2026-11-13 10:00" },
    { "name": "remark",   "value": "请及时处理" }
  ],
  "url": "https://example.com/ticket/A-20261113-001",
  "miniprogram": {
    "appId": "wx62c3973df7065a2b",
    "pagePath": "pages/launch/launch?app=pco"
  },
  "targets": {
    "openids": ["oXXXXXXXXXXXXXXXXXXX"]
  },
  "clientMsgId": "ticket-A-20261113-001-created"
}
```

字段说明：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `templateId` | string | 是 | 公众号模板 ID |
| `data` | array | 是 | 模板变量，元素为 `{name, value, color?}`；必须覆盖模板里全部 `{{xxx.DATA}}` |
| `url` | string | 否 | 点击消息跳转的 H5 地址，需为已备案域名 |
| `miniprogram` | object | 否 | 点击跳转小程序，见 3.4 |
| `targets` | object | 是 | 收件人，四个数组至少要有一个非空，见第四节 |
| `clientMsgId` | string | 否 | 幂等键，见第七节 |
| `sendType` | string | 否 | 预留字段，当前忽略，一律按模板消息发送 |

请求体里多传的字段会被忽略，不影响调用。

### 3.3 data 规则

- `name` 必须与模板里的变量名**完全一致**（含大小写），如 `keyword1`、`thing2`、`remark`
- 模板里出现的每个变量都必须提供，缺哪个就在错误信息里报哪个
- 多传的变量会被忽略，不影响发送
- 值统一按字符串传，数字、日期也写成字符串
- `color` 可选，微信官方支持的颜色值（如 `#173177`），不传用默认色
- 值的长度与格式由微信按模板字段类型校验，本服务不做二次校验；超限会在发送结果里以微信原始错误体现

### 3.4 跳转配置

`url` 和 `miniprogram` 可以只传一个，也可以都传。都传时，新版本微信优先打开小程序，老版本打开 `url`。

`miniprogram` 字段：

| 字段 | 说明 |
| --- | --- |
| `appId` | 小程序 appid，注意是**驼峰** `appId`，不是 `appid` |
| `pagePath` | 小程序页面路径，如 `pages/launch/launch?app=pco`，注意是**驼峰** `pagePath`，不是 `pagepath` |

> ⚠️ 这两个字段名写成微信官方文档里的 `appid` / `pagepath` 会被服务端当作未知字段丢弃，消息仍然发送成功，但**点不开小程序**。

小程序必须与该公众号在同一开放平台帐号下，否则点击无法跳转。

## 四、收件人规则

### 4.1 基本规则

`targets` 支持四种来源，**可以组合**：

| 字段 | 类型 | 匹配方式 |
| --- | --- | --- |
| `openids` | string[] | 精确匹配该公众号的粉丝 openid |
| `phones` | string[] | 精确匹配粉丝手机号，必须唯一对应一个粉丝 |
| `nicknames` | string[] | 精确匹配粉丝昵称，重名时**全部发送** |
| `tagids` | number[] | 公众号标签 ID，展开为该标签下已关注的粉丝 |

规则：

1. **至少填一个**。四个数组全空或都不传 → 400
2. 填了多个就**取并集**，同一个人只发一次
3. 任一目标在系统里**不存在**，整批 400，一条都不发，不会「能发的先发」
4. 任一目标**已取关**，整批 400，返回取关清单（`tagids` 展开时只取已关注粉丝，不受此条影响）
5. 数组元素总数超过 100，或并集去重后超过 100 人 → 400，请分批调用

### 4.2 各来源的细节

#### openids

- 必须是该密钥所属公众号下的 openid
- 不在粉丝表中 → 400，错误信息列出全部缺失项

#### phones

- 只匹配粉丝档案里的手机号，不匹配小程序用户档案
- 一个手机号命中多个粉丝 → 400，不做猜测
- 错误信息里的手机号是打码的（`138****0000`），按打码结果对照即可
- 粉丝表里的手机号由其他业务流程回填，命中率取决于该公众号的数据情况；接入前建议先用少量手机号试调

#### nicknames

- 精确匹配，不做模糊查询
- 重名会全部发送，实际收件人数可能大于你传的昵称个数
- 昵称随时可能被用户修改，不适合做长期标识

#### tagids

- 标签必须存在于该公众号，否则 400
- 只展开**已关注**的粉丝；标签下的历史取关用户会被跳过，不会让整批失败
- 标签下没有粉丝不算错误，只是贡献 0 个收件人；如果最终总数为 0，返回 400「没有解析到任何收件人」

### 4.3 组合示例

```json
{
  "targets": {
    "openids": ["oAAA", "oBBB"],
    "phones": ["13800000000"],
    "tagids": [101]
  }
}
```

假设 `oAAA` 也在标签 101 里，最终收件人是 `{oAAA, oBBB, 138 对应的粉丝, 标签 101 下的其他人}`，去重后逐条发送。

## 五、响应

### 5.1 成功与部分成功

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "batchId": "b3f1c2a4d5e6478a9b0c1d2e3f4a5b6c",
    "requested": 6,
    "resolved": 5,
    "duplicate": 1,
    "successCount": 4,
    "failCount": 1,
    "failures": [
      { "openid": "oYYYY", "reason": "system error" }
    ]
  }
}
```

| 字段 | 说明 |
| --- | --- |
| `batchId` | 本次推送的批次号（32 位十六进制），排查问题时提供该值 |
| `requested` | 请求里四个数组的元素总数 |
| `resolved` | 解析去重后的收件人数 |
| `duplicate` | 被去重掉的人数（同一人被多个来源重复指定）；`tagids` 展开带来的人数不计入 |
| `successCount` | 发送成功条数 |
| `failCount` | 发送失败条数 |
| `failures` | 发送阶段的失败明细，最多返回 50 条；完整记录可凭 `batchId` 在服务端查询 |

**部分成功也返回 `code=200`**。判断是否全部送达要看 `failCount`，不能只看 `code`。

### 5.2 错误响应

```json
{
  "code": 400,
  "msg": "以下 openid 不在公众号粉丝中：o1, o2"
}
```

> ⚠️ **HTTP 状态码正常都是 200，业务失败也是 200**，结果在响应体的 `code` 字段里。只判断 HTTP 200 会把失败当成功。

### 5.3 错误码

| `code` | 含义 | 是否可重试 |
| --- | --- | --- |
| 200 | 成功，或部分成功（看 `failCount`） | — |
| 400 | 参数错误 / 模板不存在 / 收件人不满足要求 | 否，按 `msg` 修正后重发 |
| 401 | 推送密钥无效 | 否，检查 `X-Notify-Secret` |
| 500 | 服务端异常 | 可重试，建议带同一个 `clientMsgId` |

`400` 的错误信息是**聚合**的，一次会把能查出来的问题都列出来，多行用 `\n` 分隔：

```text
以下 openid 不在公众号粉丝中：o1, o2
以下手机号无法解析到粉丝：138****0000
以下手机号对应多个粉丝，无法确定收件人：139****0001
以下昵称查不到粉丝：张三
以下 tagid 不存在：101, 102
```

校验类错误全部在**发送前**抛出，返回 4xx 时一条消息都没有发出，可以放心修正后重试。

其他 400 文案：

| `msg` | 含义 |
| --- | --- |
| `至少指定一个推送目标` | `targets` 四个数组全空 |
| `收件人总数 N 超过单次上限 100，请分批` | 数组元素总数超限 |
| `解析后收件人 N 超过单次上限 100，请分批或缩小标签范围` | 标签展开后人数超限 |
| `模板不存在或尚未添加到该公众号：xxx` | 本地和微信侧都没有这个模板 |
| `模板字段缺失，未提供：keyword1, remark` | `data` 没覆盖模板变量 |
| `以下用户已取关，无法推送：o3, o4` | 命中已取关粉丝 |
| `没有解析到任何收件人` | 标签存在但展开后为空 |
| `拉取公众号模板失败：xxx` | 微信接口异常 |
| `拉取标签失败：xxx` | 微信接口异常 |

## 六、发送节奏

服务端对单个公众号**串行逐条发送**，每条间隔 50ms，不做并发，也不做自动重试。100 人满额时，仅间隔就约 5 秒，加上微信接口耗时，整体可能到十几秒。

微信模板消息本身还有账号级的日调用额度限制，额度用尽时发送会失败并计入 `failCount`。大批量推送请自行控制节奏：

- 单次不超过 100 人，超出自行分批
- 批次之间留出间隔，不要连续打满
- 同一个公众号不要多路并发调用

## 七、幂等与重试

### 7.1 clientMsgId

`clientMsgId` 是调用方生成的幂等键，建议用业务事件 ID，例如 `ticket-A-20261113-001-created`。

- 同一个 `clientMsgId` 重复请求，服务端**直接返回首次的批次结果**，不会重复发送
- 不传 `clientMsgId`，每次请求都会真实发送
- 幂等范围是单个公众号，不同公众号可以复用同一个值
- 幂等结果里 `failures` 为空，只有计数；需要明细请用 `batchId` 查服务端日志
- **一个 `clientMsgId` 只对应同一份请求内容**。请求被 400 拒绝后，修正内容重发时请换一个新的 `clientMsgId`

### 7.2 重试建议

| 场景 | 做法 |
| --- | --- |
| 网络超时 / 连接中断 | 带同一个 `clientMsgId` 重试 |
| `code=500` | 退避后重试，同样带 `clientMsgId` |
| `code=400` / `401` | **不要重试**，按 `msg` 修正，并换新的 `clientMsgId` |

### 7.3 超时设置

同步接口，建议连接超时 5s、读取超时 60s。超时不代表没发出去，用 `clientMsgId` 重试即可拿到首次结果。

## 八、调用示例

### 8.1 curl

```bash
curl -X POST 'https://wechat.bleem.site/wx/push/template' \
  -H 'Content-Type: application/json; charset=utf-8' \
  -H 'X-Notify-Secret: 0123456789abcdef0123456789abcdef0123456789abcdef' \
  -d '{
    "templateId": "9bRzXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX",
    "data": [
      { "name": "keyword1", "value": "A-20261113-001" },
      { "name": "keyword2", "value": "2026-11-13 10:00" }
    ],
    "targets": { "openids": ["oXXXXXXXXXXXXXXXXXXX"] },
    "clientMsgId": "ticket-A-20261113-001-created"
  }'
```

### 8.2 Java

```java
// body 为 3.2 节的 JSON 字符串，secret 为推送密钥，均按 UTF-8 编码
HttpRequest request = HttpRequest.newBuilder()
        .uri(URI.create("https://wechat.bleem.site/wx/push/template"))
        .header("Content-Type", "application/json; charset=utf-8")
        .header("X-Notify-Secret", secret)
        .timeout(Duration.ofSeconds(60))
        .POST(HttpRequest.BodyPublishers.ofString(body, StandardCharsets.UTF_8))
        .build();

HttpResponse<String> response = HttpClient.newHttpClient()
        .send(request, HttpResponse.BodyHandlers.ofString(StandardCharsets.UTF_8));

// 注意：HTTP 状态码恒为 200，成败看响应体里的 code
JSONObject json = JSON.parseObject(response.body());
if (json.getIntValue("code") != 200) {
    throw new IllegalStateException("推送失败：" + json.getString("msg"));
}
JSONObject data = json.getJSONObject("data");
if (data.getIntValue("failCount") > 0) {
    log.warn("部分失败，batchId={}, failures={}",
            data.getString("batchId"), data.getJSONArray("failures"));
}
```

## 九、排查清单

| 现象 | 可能原因 |
| --- | --- |
| 404 | 地址写错，或路径少了 `/wx` |
| 401 | 密钥填错、多了空格、用了别的公众号的密钥 |
| 400 模板不存在 | 模板还没在该公众号后台添加，或 `templateId` 抄错 |
| 400 模板字段缺失 | `data` 没覆盖模板全部 `{{xxx.DATA}}`，按 `msg` 补齐 |
| 400 openid 不在粉丝中 | 用了小程序的 openid，或用户已不在该公众号粉丝表里 |
| 400 已取关 | 用户取消了关注，需换其他渠道通知 |
| 400 超过上限 | 解析后超过 100 人，拆成多次调用 |
| 200 但 `failCount > 0` | 发送阶段被微信拒绝，看 `failures[].reason` 里的原始错误 |
| 消息收到但点不开小程序 | `miniprogram` 里写成了 `appid` / `pagepath`，应为 `appId` / `pagePath` |
| 用户收不到但接口成功 | 检查用户是否已关注、微信客户端是否屏蔽了该公众号消息 |
